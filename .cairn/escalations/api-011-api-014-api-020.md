DECISION

Question:   May we mark iTerm2 3.7 inline-image color and transparency as unsupported while retaining the public inline-image APIs and completing the rest of this commitment?
Recommend:  Yes. Preserve the APIs and all other acceptance requirements. Explicitly document this host/version limitation, retain its failing evidence, and use already-verified WezTerm for inline-protocol acceptance.
Because:    iTerm 3.7 shifts colors and paints white behind transparent pixels in an independently generated PNG. The identical PNG renders exact colors and transparency in an independent AppKit window. Explicit sRGB/ICC profiles and disabling Metal do not fix iTerm. Repairing the host terminal falls outside this library commitment.
If wrong:   iTerm 3.7 users would still see those defects, so its color/transparency support must not be claimed until the host is repaired. The public API would remain available with that explicit limitation.
Instead:    Keep full iTerm 3.7 acceptance mandatory and leave this commitment blocked until an upstream fix or a separately agreed host repair passes the existing image checks.
