DECISION

Question:   May Updater require a real update method, meaning existing empty implementations must add that method?
Recommend:  Require the update method and let each App own registered updaters. Request handles wake only their App, coalesce repeated requests, and invoke pending updaters in registration order before rendering; removed registrations and closed Apps make old handles inert.
Because:    Updater currently has no methods or dispatch path. A required method makes the promised refresh behavior explicit and prevents an empty implementation from silently doing nothing. The proposed contract and acceptance cases are recorded in .cairn/reviews/api-019-updater-contract.md.
If wrong:   Downstream code using impl Updater for T {} must add the method. No such implementations were found in this repository, but external users may have them.
Instead:    Preserve source compatibility by keeping the marker trait and require an explicit callback when registering an updater. This changes the contract so callbacks, rather than a method on Updater, perform refreshes.
