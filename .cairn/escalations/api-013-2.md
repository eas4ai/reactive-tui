DECISION

Question:   May current-value animations require a target handle from the owning App or ScreenManager, replacing ID-only calls for relative values?
Recommend:  Use a target handle: a reference to one element in a specific App or screen. It reads the actual current properties when playback starts, with checked errors for missing targets or invalid relative expressions. Preserve explicit from-to animation construction. Relative callers must obtain and pass the handle instead of a string ID.
Because:    The new regression paints a target at 50 percent opacity, then requests +0.25; animate currently discards the ID and starts at zero. A string alone cannot identify which App or screen owns that ID. There is no existing current-property binding, and the production standard requires approval for public compatibility changes.
If wrong:   Existing relative-animation callers need migration. The new handle must have clear lifetime and per-target behavior so removal and duplicate IDs in different Apps cannot read another target. Screen input and transition repairs are committed and tested; API-013 remains incomplete.
Instead:    Keep ID-only calls and resolve them through an implicit current-App or current-screen context. This preserves calls made inside that context, but calls made outside it need a defined error and callers must enter the correct context. Do not retain zero as a guessed current value.
