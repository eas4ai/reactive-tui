DECISION

Question:   May App performance metrics and mode changes use an explicit App handle, while legacy global functions serve only standalone hooks?
Recommend:  Yes. Give each App its own PerformanceContext, expose App::performance_context(), and supply it automatically to component hooks. Keep the global APIs for standalone callers.
Because:    A real two-App probe changed the first App signal from 30 to 144 FPS when the second ran; both reported Auto. The global request queue has no App identity. The concrete proposal is in .cairn/reviews/api-019-performance-owner/review.md.
If wrong:   External code that reads or controls an App through global performance functions must migrate to its App handle or component hooks. Apps will no longer publish into or consume the standalone global state.
Instead:    Keep process-global performance routing and explicitly limit this performance API family to one App per process, dropping its multi-App isolation guarantee.
