Question:   May gesture distances and velocity use the units of the input event: cells for cell input and pixels for pixel input, instead of promising pixels on every terminal?
Recommend:  Preserve both Position variants and all hook signatures. A drag threshold of 5 means five cells on cell input and five pixels on pixel input; velocity uses those units per second. Restart a gesture if its coordinate units change.
Because:    Crossterm supplies cell positions, while DirectTty can also supply pixels. The public distance helper currently measures cells and discards pixel distances; its failing consumer is recorded in .cairn/reviews/api-019-gesture-units. Cell movement alone cannot establish physical pixel distance.
If wrong:   Callers interpreting the existing pixel documentation literally may need to adjust thresholds on cell-based terminals. Five cells can be a much larger movement than five pixels.
Instead:    Keep unconditional pixel thresholds and add measured host cell dimensions before converting cell input. This requires additional terminal capability and resize checks plus explicit behavior when a terminal cannot report those dimensions.
